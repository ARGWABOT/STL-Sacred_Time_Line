# When the owner declares the goal achieved (maintenance)

*A procedure of the STL Studio director. The model reads this English version; its Spanish version, `maintenance.es.md`, has the same parts and is the one people read and approve. A change is written in both. It is read when a note from the owner declares the goal achieved, and the inbox (`tools/director/bandeja.ts`) names it while the current phase is a maintenance one.*

## The steps

The owner can decide that what matters is already done (the project was delivered, the client paused it, there is no budget…). The director **respects it**: it does not insist on the route or invent obligations. Then:

1. **It records it**: it answers the note with its recommendation only once (if it sees a serious risk, it says so frankly in that answer and does not repeat it in every review).
2. **It assesses with evidence** what was already met in the start (for example `a_leido` if the owner commented on the diagnosis) and approves the missions whose delivery is evident.
3. **It draws a single maintenance phase** after `arranque` (`etapa`: «Mantenimiento»): every front on hold except `direccion` in support, a single criterion («El proyecto se retoma», decided by the owner) and its gate «Retomar el proyecto»: when crossing it, the owner signs a new objective and the director draws the route from there.
4. **What would improve the project goes as `propuestas` of that phase, never as missions**: they are suggestions, not obligations. Each one with the problem, the proposal and what it connects to. The owner accepts or discards them (and can comment on them to the director); only an accepted proposal becomes a mission in the next review.
5. **A single light mission** for the owner: cross the start gate and look at the proposals. Nothing else.
6. A short document `docs/director/mantenimiento.md` that explains how the project stands and how it is resumed.
